# Project card and evidence labels

Use when building a concrete artifact. Omit fields that do not affect the decision.

| Field | Fill with |
| --- | --- |
| Problem | Person, current friction, desired change; separate facts from assumptions. |
| Source idea | Paraphrase, chapter/section or reliable locator, application conditions. |
| First artifact | One editable item applying the idea to this problem. |
| Design decision | Why this form fits the context; label as inference, not author claim. |
| Test | Who does what, when, and what will be observed. |
| Status | Draft / used but untested / tested with actual observations. |
| Next change | One change supported by feedback, or a pending observation. |

Evidence tags: `[Book]` source-grounded paraphrase; `[User]` user-provided fact; `[Design]` project-specific inference; `[Hypothesis]` uncertain benefit; `[Observed]` a real test result with method/sample. Never promote a hypothesis to observed because a draft looks convincing.

Example before the user acts:
- `[User]` “My highlighted notes feel familiar but I cannot recall them next week.”
- `[Book]` Retrieval and spaced practice are useful; cite the relevant section in the supplied edition.
- `[Design]` Create one closed-book card and retest after an interval.
- `[Hypothesis]` The card may make the idea easier to retrieve next week.
- **Status:** draft; no answers or results recorded yet.
